## Git и GitHub: в чём разница

**Git** — это распределённая система контроля версий, которая работает локально на компьютере. Она позволяет фиксировать изменения, переключаться между версиями и создавать ветки без доступа к интернету.  

**GitHub** — это облачная платформа для хостинга Git‑репозиториев. Она предоставляет интерфейс для совместной работы, код‑ревью, отслеживания задач и хранения удалённых копий проектов.  

Проще говоря, Git — это инструмент, а GitHub — сервис, который его использует.



## Что сравнивают `git diff` и `git diff --staged`

- **`git diff`** показывает различия между **рабочей директорией** и **последним коммитом** (по умолчанию). То есть вы видите изменения, которые сделали в файлах, но ещё не подготовили к коммиту (не выполнили `git add`).  

- **`git diff --staged`** (или `git diff --cached`) показывает различия между **индексом** и **последним коммитом**. То есть вы видите, какие именно изменения уже подготовлены к фиксации и попадут в следующий коммит.


## Локальные состояния Git

Git оперирует тремя основными областями, которые важно различать:

- **Рабочая папка (Working Directory)** — это файлы на вашем компьютере, с которыми вы сейчас работаете. Git видит, что они изменились, но пока не «запомнил» эти изменения. Это зона активной разработки.  

- **Индекс (Staging Area)** — это промежуточная область («черновик»), куда файлы попадают после команды `git add`. Здесь вы собираете именно те изменения, которые хотите зафиксировать в следующем коммите.  

- **Коммит** — это сохранённый снимок (версия) проекта в истории Git. Когда вы выполняете `git commit`, Git навсегда записывает в историю состояние файлов, которые на тот момент находились в индексе.



git status: показывает текущее состояние репозитория. Он сообщает, какие файлы изменены, какие добавлены в индекс (staged), а какие Git вообще не отслеживает. Это «чек-лист» перед коммитом.
git diff: показывает разницу между рабочей директорией и индексом (то есть изменения, которые вы ещё не добавили через git add). По умолчанию он подсвечивает только незакоммиченные правки.
git diff --staged: показывает разницу между индексом и последним коммитом. Это позволяет увидеть, что именно уйдёт в следующий коммит после git commit. Флаг --staged (синоним --cached) фильтрует только подготовленные файлы.
